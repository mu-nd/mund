# 値の抽出(独立二重入力・比較・判定・承認)

論文の値をデータにするときは、同じ文献について **2つの独立した入力 A・B** を作り、
**比較** し、違いを **判定** し、**責任者が承認** してから `data/` に **登録** します。
入力ツールの **値の抽出** ページで行います。作業中のファイルは `data/` とは別の作業領域
`extraction/<タスク名>/` に置かれ、承認された値だけが `data/` に入ります。

## 1. 流れ

1. **タスクを作る**: タスク名(英数字と `. _ -`、例 `Suzuki1987`)、DOI、**読んだ版**(出版社版、
   `arXiv:2501.05897v2` など)、PDF を指定します。PDF は SHA-256 と大きさだけが記録されます(6節)。
   登録先のデータ種別(EXP / TH / CUR / EVAL)、新しいデータセットになるときの施設、メタデータの Key も
   ここで決めます。
2. **表・図の一覧**: 値が載っている可能性のある表・図・本文の箇所をすべて挙げます(「概要」)。
3. **入力 A・B**: それぞれ「人が入力する」「AI に入力させる」「AI の下書きを人が直す」のどれかで作ります。
   各入力は一覧の箇所すべてに「値あり」「該当なし」(決められないときは「要確認」)を付け、値を1行ずつ
   入力して **提出** します。提出した入力は変更できません。
4. **比較・判定**: 両方が提出されると、A と B が並べて表示されます。違いのある行・片方にしかない行・
   印の違う箇所のそれぞれについて、何を採用するかを理由とともに記録します。
5. **承認**: 責任者が内容を確認して承認します。A と B が一致していても、承認がなければ登録できません。
6. **データに登録**: 承認された行が `data/LT/<種別>/…json` に書き込まれ、ふだんの保存と同じチェックを
   通って保存・送信されます。

入力の方法(人 / AI)とデータ種別は関係ありません。AI が読み取った実験値も EXP です。

## 2. 入力の方法と独立性

| 方法 | `mode` | 記録されるもの |
|---|---|---|
| 人が入力する | `human` | 入力した人 (`extractor`) |
| AI に入力させる | `ai` | モデル ID・プロンプトの版・実行時刻 (`run`)。作られた時点で提出済み |
| AI の下書きを人が直す | `assisted` | AI の下書き (`aiDraft`: その実行記録と内容、変更されない) と、直した人 |

2つの入力が **独立** とみなされるのは、どちらも相手の入力からも共通の AI 出力からも影響を受けえない組です。

| 組み合わせ | 独立か |
|---|---|
| 人 + 人(別の人) | 独立 |
| 人 + AI | 独立 |
| 人 + AI の下書きを人が直したもの | 独立 |
| AI + AI、AI + AI 下書き、AI 下書き + AI 下書き | 独立ではない(両方に AI の出力が含まれる。AI の下書きを直した入力は AI の出力から独立していない) |
| 同じ人による2つの入力 | 独立ではない |

独立かどうかは「概要」「比較・判定」「承認・登録」に表示されます。

## 3. ブラインド

- 一方の入力の内容は、**両方が提出されるまで表示されません**。入力中の内容は、その入力の画面でだけ表示されます。
  提出した入力も、もう一方が提出されるまでは表示されません。
- ほかの人が担当している入力中の入力を開くときは、確認が表示されます。
- AI には PDF とタスクの表・図の一覧だけを渡します。もう一方の入力は渡しません。
- 入力のファイルはリポジトリに保存されるので、ブラインドは画面の上の約束です。もう一方の入力を担当している人は、
  提出するまで相手のファイルを開かないでください。

## 4. 比較の規則

**行の対応付け**(リストの順番は使いません)

1. 核種(元素と質量数。質量数 0 = 天然同位体比 は、どの同位体とも別)、量(寿命・捕獲率・捕獲確率)、条件ラベルが
   同じ行どうしを組にします。同じ組み合わせが複数あるときは、位置(頁・表/図・行/ラベル)が同じものを組にします。
2. それでも残った行が A と B に1行ずつなら、その2行を組にし、位置の違いを表示します。
3. それ以外の行は「A のみ」「B のみ」になります。元素が同じで質量数(天然/同位体)・量・条件だけが違う行があれば、
   そのことを示します。

**比べるもの**

- 位置、**原表記**(印刷されたとおりの値・単位・不確かさの文字)、**換算後の値**、不確かさ(全体・統計・系統ごと)、
  要確認の印、片方にしかない行、表・図ごとの印。
- 原表記の比較と換算後の比較は別に表示されます。例: `0.880 µs` と `880 ns` は原表記が違い、換算後は一致するので
  「単位のみの違い」になります。
- 単位の違いは 10 のべきなので、換算は桁をずらすだけで、丸めはありません。**許容幅はありません**。
  一致とは、同じ文字(原表記・書かれた数値)または換算後の値が厳密に等しいことです。それ以外はすべて表示されます。

| 表示 | 意味 |
|---|---|
| 単位のみの違い | 換算後の値も桁数も同じ(`0.880 us` / `880 ns`) |
| 表記のみの違い | 単位・値・桁数が同じで書き方だけ違う(`8.80e2` / `880`) |
| 桁数の違い | 換算後の値は同じで、書かれた桁数が違う(`880` / `880.0`) |
| 値の違い | 換算後の値が違う |

## 5. 判定

| 判定 | 記録 |
|---|---|
| 一致(そのまま採用) | A と B がまったく同じ(位置・原表記・値・単位・不確かさ)で、どちらにも要確認がない行。理由は不要 |
| A を採用 / B を採用 | その入力の行をそのまま採用 |
| 修正して採用 | 直した行を採用(両方にない行を加えることもできる) |
| 採用しない | 行を採用しない |

一致以外の判定と、A・B の印が違う箇所(または印のない箇所)の判定には、**理由・判定した人・時刻** が記録されます。
採用した行の「条件」は登録されるデータの Key に、「データのコメント」はデータの comment になります。

## 6. 承認

承認は、次の内容の SHA-256(**承認のハッシュ**)に結び付けて記録されます。

- タスク名、文献(DOI・読んだ版・**PDF の SHA-256 と大きさ**・表/図の一覧)、登録先
- 入力 A と入力 B(それぞれの内容のハッシュ)
- 判定(採用した行、採用しない行、箇所の判定。承認そのものは含まない)

ハッシュは、キーを並べ替え空白を除いた JSON(数値は書かれたとおり、`entryHash` と同じ方法)の SHA-256 です。
承認の後に何かが変わると、承認は無効になり **「再確認が必要」** と表示されます。承認し直すまで登録できません。
承認は、ツールに記録されている保存する人の名前(`pixi run login` で決まる)で記録されます。

## 7. データに登録

「データに登録」は、承認された行を登録先のファイル(DOI・種別・Key で決まる MetaID のファイル。なければ新しく作る)に
書き込み、ふだんの保存と同じチェックを通して保存・送信します。同時に `task.json` の `publications` に、
登録した datasetId とその entryHash、承認のハッシュ、登録した人と時刻が記録されます。

ツールのサーバーは次の場合に登録を断ります。

- 両方の入力が提出されていない、承認されていない、承認の後に内容が変わった
- 判定していない行・箇所がある、採用した行が入力の行と合わない
- 登録先に同じ datasetId の行があり、それがこのタスクから登録したものでない
- このタスクから登録した行が、その後データセットの画面で変更されている
- 以前このタスクから登録した行が、承認された結果にない(先にデータセットの画面で削除する)

同じ承認内容でもう一度登録すると、このタスクから登録した行が同じ場所で置き換えられます。

## 8. AI による抽出

- AI は入力ツールのサーバー(このコンピュータの Python)が呼び出します。ブラウザの中には API キーはありません。
- API キーはツールを起動した環境の `ANTHROPIC_API_KEY`(または `ANTHROPIC_AUTH_TOKEN`)から読みます。
  SDK は `pixi run -e ai admin` で起動したときに入ります。キーか SDK がなければ「利用できません」と表示されます。
- モデルとプロンプトの版は `tools/mundlib/extraction_ai.py` にあり、入力の `run` に記録されます
  (拒否されたときに別のモデルに引き継がれた場合は、実際に答えたモデルが `model` に入ります)。
- AI は読み取れない箇所を推測せず、空欄にして理由を書きます。数として読めない値、量に合わない単位、
  読めない核種の行は「要確認」になり、核種・値・単位は入りません。印を付けなかった箇所も「要確認」になります。
- 「AI の下書きを人が直す」では、下書きが `aiDraft` にそのまま残り、人が直した行が提出されます。

## 9. ファイル

```
extraction/<タスク名>/task.json           文献・PDF の SHA-256 と大きさ・表/図の一覧・登録先・登録の記録
extraction/<タスク名>/input-A.json        入力 A
extraction/<タスク名>/input-B.json        入力 B
extraction/<タスク名>/adjudication.json   採用した行・採用しない行・箇所の判定・承認
extraction/<タスク名>/source.pdf          PDF(このコンピュータだけ。.gitignore で除外され、保存・送信されない)
```

形式は `schema/v1/extraction-task.schema.json`、`extraction-input.schema.json`、
`extraction-adjudication.schema.json` にあり、`data/` のファイルと同じ正規の書式(1行1データ、数値は書かれたとおり)で
書かれます。入力の1行は次のようになります。

```json
{"id": "r2", "location": {"page": "3", "item": "Table 1", "label": "Si"}, "nuclide": {"element": "Si", "mass": 0}, "kind": "lifetime", "original": {"value": "0.7566", "unit": "μs", "uncertainty": "± 0.0010"}, "value": 0.7566, "unit": "us", "uncertainties": [{"source": "total", "value": 0.0010}]}
```

`original` には印刷された数値・単位・不確かさの文字だけを書き、文章は写しません。リポジトリは公開されているので、
PDF や論文の文章はリポジトリに入れません。メモ (`notes`) も自分の言葉で短く書きます。

## 10. 何がどこで守られるか

| 規則 | 画面 | サーバー(保存・登録のとき) |
|---|---|---|
| 形式(スキーマ)と正規の書式 | 表示 | 拒否 |
| ブラインド(両方の提出まで相手を表示しない) | ○ | —(ファイルはリポジトリにある) |
| 提出済みの入力は変更・削除できない | ○ | 拒否 |
| AI の入力と AI の下書きは AI の実行だけが書く | ○ | 拒否 |
| AI にもう一方の入力を渡さない | — | ○(PDF と表/図の一覧だけを送る) |
| 提出には全箇所の印が必要 | ○ | 拒否 |
| 入力は同じ PDF について作られている | 表示 | 提出済みなら拒否 |
| 比較は両方の提出後 | ○ | 拒否 |
| 採用した行は入力の行どおり(一致は完全一致だけ) | ○ | 拒否 |
| 承認は保存する人の名前で、保存する内容について | ○ | 拒否 |
| 判定の残っている結果は承認できない | ○ | 拒否 |
| 未承認・承認後に変わった結果は登録できない | ○ | 拒否 |
| 登録の記録は登録だけが書く | — | 拒否 |

チェックの順番や内容は `tools/mundlib/extraction.py`(サーバー)と `admin/js/extraction.js`(画面)にあり、
承認のハッシュが両者で同じになることを `tests/vectors/extraction.json` で確かめています。

ツールを通さずに書き換えられた場合に備えて、`python3 tools/mund.py validate`(変更のたびに CI で実行)も
保存されている作業領域を検査します。各タスクのファイルの形式と状態の規則(上の表のうち、変更の前後を比べるもの以外)、
タスクのフォルダーに決まったファイル以外がないこと(エラー)、最後の登録のあとにタスクが変わっていないこと
(`W_EXTRACTION_CHANGED`)、登録したエントリーが `data/` にそのまま残っていること
(`W_PUBLISHED_MISSING`、`W_PUBLISHED_CHANGED`。登録後の訂正はありうるので警告)です。
