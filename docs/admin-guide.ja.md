# データ入力ツールの手引き

データベースの追加・修正は、自分のコンピュータで動く入力ツールで行います。
ファイルを開いて編集し、**保存** を押すと、内容がチェックされて記録され、GitHub
(`mu-nd/mund`)に送信されます。公開サイト(`https://ribf.riken.jp/muon/`)には、
送信から数分後に反映されます。

ツールの **使い方** ページに要点があります。詳しくはこの手引きを見てください。

## 1. 最初に一度だけ行う準備

1. **pixi** をインストールします(<https://pixi.sh> の手順どおり。ターミナルに1行貼り付けるだけです)。
2. データを取得します。ターミナルで

   ```
   pixi exec --spec git -- git clone https://github.com/mu-nd/mund
   cd mund
   ```

   `mund` というフォルダができます。以後はこのフォルダで作業します。
3. GitHub にログインします(一度だけ)。

   ```
   pixi run login
   ```

   ブラウザが開いたら、GitHub アカウントで許可します。保存者の名前とメールアドレスが両方とも設定されていれば、その組み合わせが使われます。
   どちらかが未設定なら、GitHub の表示名(なければユーザー名)と、そのアカウントの非公開用メールアドレスが設定されます。
   最後にターミナルに表示される名前とメールアドレスが自分のものか確認してください。

   アクセストークンは GitHub CLI が OS の資格情報の保管場所(macOS のキーチェーン、Windows の資格情報マネージャーなど)に保存します。
   その保管場所が使えない場合は、GitHub CLI の設定ファイル(通常は `~/.config/gh/hosts.yml`)に保存します。
   ブラウザでのログインは、このリポジトリ以外にも使える広い権限になります。権限をこのリポジトリだけに
   絞りたいときは、GitHub の Settings → Developer settings → **Fine-grained personal access tokens** で、
   対象を `mu-nd/mund` だけ、権限を **Contents: Read and write** だけにしたトークンを作り(有効期限を付けます)、

   ```
   pixi run login --with-token
   ```

   を実行し、入力を求められたらトークンを貼り付けて Enter を押します。入力中のトークンは画面に表示されません。
   トークンをコマンドに直接書くと履歴に残ります。
   トークンの期限が切れたり取り消したりすると、送信のときに「GitHub へのログインが必要です」と表示されます。
   新しいトークンで同じ手順をもう一度行い、**再送信** を押せば、保存済みの変更がそのまま送信されます。

## 2. 毎日の使い方

1. ターミナルで `mund` フォルダに移り、`pixi run admin` を実行します。ブラウザでツールが開きます。
   起動すると、ツールはまず GitHub の最新の状態を取り込みます。ツールは一度に1つのタブでだけ動き、
   別のタブで開くと、それまでのタブは入力内容を引き渡して使えなくなります。
   まだ保持できない入力(文献の入っていない新しいファイルなど)や未選択の ID の変更があるときは、それまでのタブが残ります。新しいタブは、そのタブを閉じるまで待ちます。
2. **データセット** でファイルを開くか、右上の **+ EXP**(理論は + TH、キュレーションは + CUR、評価は + EVAL)で
   新しく作ります。
3. 編集して **保存** を押します。
4. 終わるときは、ターミナルで Ctrl+C を押します。

### 論文を1本登録する

1. **文献** カードの **文献 (bibId)** 欄に DOI を入力して **書誌情報を取得** を押します(`DOI:` は自動で付きます)。著者・誌名・年などが
   Crossref または DataCite から入ります。内容を確認してください。書誌情報は文献データベース
   (`data/master/bibliography.json`)に記録されます。
   - DOI のない文献は、[NSR](https://www.nndc.bnl.gov/nsr/) のキー番号を入力します
     (例 `1987SU06`。`NSR:1987SU06` になります)。書誌情報は NSR のページを見て手で入力します。
   - DOI も NSR のキー番号もない文献は **DOI なし…** を押し、名前(例 `Suzuki1975thesis`)を付けます
     (`muND:Suzuki1975thesis` になります)。書誌情報と、文献の所在(URL)は手で入力します。
   - arXiv 版・訂正・データの DOI は「関連する文献」に入れます。
   - **枝番 Key(任意)** は、1つの論文に測定条件の異なるメタデータを複数作る場合だけ使います
     (例 `setup-b`)。文献と Key から MetaID が決まり、その下に表示されます。
2. **実験条件** カード: 施設を選び、測定手法・ビーム・標的・検出器を書きます(自由記述)。
   施設が一覧にない場合は **マスタデータ** で追加してから選びます。
   (TH・CUR・EVAL では「値の導出方法」カードで手法やコメントを書きます。)
3. **データ** カード: **+ 行を追加** で1行ずつ入力するか、**貼り付け…** で表計算ソフトから
   まとめて貼り付けます。
   - 貼り付けの列の順番は 元素, 質量数, 値, 不確かさ, [Key], [コメント]
   - 貼り付けの質量数は整数か `nat` で書きます(`28.0` のような小数の行は読み取られません)
   - 質量数 0 は天然同位体比の標的です
   - 値と不確かさは**論文に書かれた桁のまま**入力します(例 `13.250`)
   - 不確かさは数値だけを書きます(例 `5.0`)。`±5.0` のような表記の行は読み取られません。論文に不確かさがない場合は空欄にします
   - 論文が統計誤差と系統誤差を分けて書いている場合は、カードの上の
     **統計・系統誤差を分けて入力** にチェックを入れ、「± 統計」「± 系統」の列に入力します
     (論文に全体の誤差もあれば「± 全体」に入力します。換算にはその値を使い、空欄なら各成分の二乗和の平方根を使います)
   - 実験データには、寿命・捕獲率・捕獲確率のうち**論文に最も近い量を1つだけ**入力します
   - 同じ核種の行が複数あるときは行の **Key**(例 `plate` / `powder`)で区別します
4. 表の右側を確認します。
   - **換算値**: 寿命を入れた行には捕獲率が、捕獲率・捕獲確率を入れた行には寿命が出ます
   - **確認**: 評価値と大きくずれていると「⚠ 要確認」になります(元素や桁の打ち間違いの発見用。
     本当にずれているデータならそのままで構いません)
   - **datasetId**: 自動で計算されます
5. 画面下の **チェック結果** にエラーがないことを確認します。エラーがあると保存できません。警告は内容を確かめ、データが正しければそのまま保存できます。
   項目を押すと該当の欄に移動します(その欄は赤または黄色で示され、マウスを重ねると内容が出ます)。
6. 画面上部の **保存** カードで、必要なら「変更の説明」(何を、なぜ変えたか)を書き、**保存** を押します。

キュレーションデータ(**+ CUR**)では、各行の「元データ」に元になった実験データの datasetId を指定します。
「…」ボタンを押すと、同じ元素の実験データの一覧から選べます。キュレーション・評価データの値は
捕獲率(µs⁻¹)に統一します。

元データを選ぶ(または datasetId を入力する)と、そのときの元データの内容(`entryHash`)も一緒に記録されます。
後で元データの値・不確かさ・単位・核種が直されると、その行の「元データ」欄に **再確認が必要** と表示され、
チェック結果にも警告が出ます。

1. **再確認が必要** を押すと、元データの現在の値とこの行の値が表示されます。
2. この行の値が元データの現在の値に合っているか確かめ、必要なら値を直します。
3. **確認しました** を押すと、元データの現在の内容が記録され、表示が消えます。

ツールが自動で「確認済み」にすることはありません。以前の ID で元データを挙げている場合は
**現在の ID に直す** で直せます(記録された内容はそのまま残ります)。

### 保存

保存していない変更があると、ページの上に保存カードが出ます。**保存** を押すと、それらがすべてまとめて
保存されます。開いているファイルのほかに、それと一緒に変わったファイル(書誌情報を取得したときの文献データベース、
ID が変わったときに書き換えられるキュレーションデータ、ファイル名が変わったときの元のファイル)も含まれます。
保存カードの「保存されるファイル」を開くと、保存対象の一覧と、エディタで開いているファイルの差分が見えます。
ほかのファイルは名前を押すと差分が開きます。「保存されるファイル」は通常は閉じており、
「ほかの人が先に変更」と表示されるファイルがあるときは最初から開いています。

- 保存のたびに、変更したファイルを表す説明(例「LT/EXP Mizuno2025 を更新」)が自動で付き、
  「変更の説明」に書いた文がその後に続きます。誰がいつ何を保存したかは、変更の説明と一緒に **履歴** で見られます。
  ツールを使わずに行われた変更は、履歴に「ツールの外で行われた変更」と表示されます。
- 保存すると「保存しました。GitHub に送信しました。」と表示されます。
- GitHub に接続できないとき(オフラインなど)は「保存しました。まだ送信していません: GitHub に接続できません。…」と
  表示され、画面上部に **未送信 n** が出ます。保存した内容はこのコンピュータにあります。接続できるように
  なったら、その隣の **再送信** を押します。
- 保存していないファイルには一覧で「未保存」と表示され、画面上部の **未保存 n** から一覧できます。
  保存していない入力は、このブラウザに残ります(ツールを終了して次に起動したときも残っています)。
  ほかのブラウザやほかのコンピュータからは見えないので、区切りのよいところで保存してください。
- 保存の処理中に入力した内容は失われません。保存が終わった後も「未保存」として残ります。
  保存できなかったとき(ツールのサーバーが応答しないときなど)も、入力内容はそのまま残ります。
- 画面上部に「入力内容をこのブラウザに保持できませんでした」と赤く表示されたら、ブラウザの保存領域が
  いっぱいか、使用が許可されていません。このときページを閉じたり再読み込みしたりすると、保存していない
  変更は失われるので、すぐに **保存** を押してください。

### 入力の途中で

入力した内容は、ツールの中では自動で保持されます(保存するまで GitHub には送られません)。保持される
ファイル名(`data/LT/EXP/Mizuno2025_4d2ed5c83736.json` のような名前)は文献・データ種別・Key と
第一著者・年から決まるので、

- **有効な文献が入るまでは入力内容を保持できません。** その間は画面上部にその旨が表示され、別のページへ
  移ることも保存することもできません。不要なら **変更を破棄** を押してください。
- **登録済みのファイルと同じ文献・データ種別・Key を入力すると、そのファイルにはなりません。** 画面上部の
  **そのファイルを開く** から登録済みのファイルを開いて、そちらに追加・修正してください。
- 第一著者や年を直すとファイル名が変わります。保存すると、元のファイルの削除と新しいファイルが一緒に
  保存されます。ファイルの **履歴** には、以前の名前での保存も表示されます。

### 最新の状態にする

画面上部の **最新にする** を押すと、GitHub からほかの人の変更を取り込み、最新の状態にします
(ツールの起動時にも自動で行われます)。入力途中の内容は失われません。

### 修正する

データセットの一覧からファイルを開いて直し、同じように保存します。

- **値・不確かさ・単位・コメント・実験条件を直しても、行を並べ替えても ID は変わりません。**
  行の追加・削除で、ほかの行の ID が変わることもありません(行は datasetId で対応づけられ、
  表の何行目かは関係しません)。
- **保存済みの行の元素・質量数・Key(またはファイルの文献・Key)を直すと ID が変わります。** このとき
  **ID が変わる行** という欄が出て、行ごとにどちらかを選ぶよう求められます。選ぶまでは保存できず、
  ほかのページへも移れません(元に戻せば欄は消えます)。
  - **同じデータの訂正**: 入力の誤りを直しただけで、同じ測定値・計算値の場合。以前の datasetId は
    その行の `legacyIds` に記録され(JSON タブで確認できます)、その行を「元データ」に挙げている
    キュレーション・評価データは新しい ID に付け替えられて、一緒に保存されます。付け替えるデータは
    欄の中に表示され、「保存されるファイル」で差分も確認できます。元素・質量数を直した場合は
    元データの内容が変わるので、付け替えたキュレーション・評価データには **再確認が必要** と表示されます
    (文献・Key だけの変更では表示されません)。
  - **別のデータ**: 以前の行とは別のデータの場合。以前の ID、`legacyIds`、訂正記録は引き継がず、
    参照も付け替えません。以前の行を「元データ」に挙げているデータはチェックでエラーになるので、
    そちらを直してから保存します。
  - 同じ保存済みの行から作った行が複数あるなど、どの行が以前の行か判別できないときは、何も付け替えず、
    以前の行は削除されたものとして扱います(欄にその旨が表示されます)。
- 削除した行を「元データ」に挙げているデータがあるときも、欄に表示され、チェックでエラーになります。
- **変更を破棄** で、そのファイルの保存していない変更を取り消せます(「同じデータの訂正」で付け替えた
  参照も元に戻ります)。
- **削除** を押すと、そのファイルを削除する変更が「未保存」の一覧に入ります。そこで **保存** を押すと
  削除が確定します。
- 変更を破棄・削除では、このファイルのために文献データベースに加えた書誌情報も、ほかのデータが
  使っていなければ取り消されます。
- 保存済みの内容を元に戻したいときは、値を直してもう一度保存します。過去の状態はすべて履歴に残っています。

### 練習する

```
pixi run admin-practice
```

で起動すると、練習用のコピーで動きます(画面に「練習用」と表示されます)。保存・送信・版の公開も
含めて全部の操作を試せますが、送信先は練習用の代わりで、本物のデータには何も届きません。ツールを
終了すると練習用のコピーは消えます。

## 3. 保存できないとき

| 表示 | 対処 |
|---|---|
| 「エラーが n 件あるため保存できません」 | 一覧のファイル名を押すと、データセットの編集画面か **マスタデータ** が開きます。データセットは画面下の **チェック結果**、マスタデータは該当の表か **ファイルを直接編集** で直します |
| 「このまま保存するとデータにエラーが生じるため、保存しませんでした」 | 表示された項目を直してから、もう一度保存します |
| 「変更を自動で合わせられなかったため、保存しませんでした」 | 下の「ほかの人が先に同じファイルを変更していたとき」 |
| 「GitHub にアクセスを拒否されました」 | データの管理者にアクセス権の確認を依頼します |
| 「GitHub へのログインが必要です」 | ターミナルで `pixi run login` を一度実行してから **再送信** を押します |
| 「保存する人の名前が分かりません」 | ターミナルで `pixi run login` を一度実行してから、もう一度保存します |
| 「このコンピュータに、記録されていない変更のあるファイルがあります」 | 何も送信されていません。データの管理者に連絡してください |
| 「記録できませんでした」 | 何も保存されていません。保存していない変更は残っているので、データの管理者に連絡してください |
| 「GitHub に接続できません」 | 保存はできています。接続できるようになったら **再送信** を押します |
| 「ほかの人の変更と自動では合わせられなかったため、送信できませんでした」 | 保存した内容はこのコンピュータにあります。データの管理者に連絡してください |
| 「ツールが処理を完了できませんでした」 | **最新にする** で保存状況を確認してから、もう一度試します |
| 「ツールのサーバーが応答しません」 | ターミナルで `pixi run admin` を起動し直します |
| 別のページに移れない | 文献が入っていないか、登録済みの文献を入れています(「入力の途中で」)。「ID が変わる行」で選んでいない行があるときも移れません(「修正する」)。JSON タブでは JSON の誤りでも移れません |

### ほかの人が先に同じファイルを変更していたとき

ほかの人が先に変更したファイルは、保存カードの「保存されるファイル」に「ほかの人が先に変更」と表示されます。
差分は**相手の変更を含む最新の内容との比較**なので、相手が変えた行は「−」に見えます。

両方の変更を自動で合わせられるときは、一緒に保存されます。合わせられないときは、何も保存されず、
「変更を自動で合わせられなかったため、保存しませんでした」と表示されます。同じ行を直した場合や、
相手が直した行のすぐ前に行を追加した場合などです。このときは次のようにします。

1. 「保存されるファイル」で差分を確認します。
2. 自分の変更を残すなら **自分の内容で上書き**、やめるなら **破棄**(開いているファイルは画面上部の **変更を破棄**)を押します。
   上書きすると、「−」の行は相手が書いたものでも取り消されます。
3. 必要ならファイルを開いて直し、もう一度 **保存** を押します。

## 4. JSON を直接編集する

エディタの **JSON** タブで、ファイルの中身をそのまま編集できます(Monaco Editor)。
スキーマに基づく入力チェックと補完(Ctrl+Space)が効きます。**反映** を押すと(または別のタブに移ると)、
ID の再計算と書式の正規化が行われてフォームに取り込まれます。行は書かれている datasetId で対応づけるので、
行を並べ替えても ID は変わりません。形式に合わないもの(使えない単位、足りない項目など)は書き換えずに
そのまま残し、チェック結果で知らせます。表で編集できない行は、表にその旨と中身が表示されるので、
JSON タブで直します。

Monaco Editor はインターネットから読み込むため、オフラインでは簡易エディタになります。簡易エディタには
スキーマのチェックと補完がありません。反映したときのチェックは同じように行われます。

**マスタデータ** ページの **ファイルを直接編集** では、施設・文献・核種表・Huff 因子・定数の各ファイルを
同じエディタで編集できます(**反映** で取り込み、**保存** で記録)。Huff 因子・定数・核種表は換算値すべてに
影響するので、慎重に変更してください。施設は同じページの「施設」の表でも追加・修正できます。

## 5. 版を公開する

**版を公開** ページで、パッチ / マイナー / メジャーを選び、変更点を書いて **vX.Y.Z を公開** を押します。
`VERSION` と `CHANGELOG.md` が保存され、その状態が版 vX.Y.Z として公開されます。保存していない変更や
エラーがあると公開できません。

- **メジャー版(v1.0.0, v2.0.0 …)だけが、公開サイトで固定版として選べるようになります。**
  外部の利用者に引用してもらうのはこの版です。
- パッチ・マイナーは履歴として残ります。
- 「公開済みの版」には、共有先で公開を確認できた版が表示されます。公開した版は後から変更できません。
- `VERSION` に書かれた版の公開が終わっていない場合(送信できなかったときなど)は、
  **vX.Y.Z の公開を完了** だけが表示されます。押すと、版番号を X.Y.Z にしたときに保存された状態を
  vX.Y.Z として公開します(その後に保存した変更は含みません)。

詳しくは `docs/versioning.md`。
