# データ入力ツールの手引き

データベースの追加・修正は、公開サイトの `/admin/`(例:
`https://niikura-muon.github.io/mund/admin/`)にある入力ツールで行います。
ローカルで試す場合は `python3 tools/mund.py serve` のあと `http://localhost:8000/admin/` です。

## 0. まず練習モードで

最初の画面で **「練習モードを始める」** を押すと、公開中のデータのコピーを使って、入力から
コミットまで全部の操作を試せます。変更はそのブラウザの中にしか保存されず、GitHub には何も
送られません。「最初の状態に戻す」でやり直せます。

## 1. GitHub に接続する

入力ツールは、あなたの GitHub アカウントの権限でリポジトリに書き込みます。
そのためのアクセストークンを一度作ります。

1. GitHub → 右上のアイコン → **Settings** → **Developer settings** →
   **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
2. **Resource owner**: リポジトリの持ち主(`niikura-muon`)
3. **Repository access**: 「Only select repositories」→ `mund` だけを選ぶ
4. **Permissions** → Repository permissions:
   - **Contents**: Read and write
   - **Pull requests**: Read and write(Pull Request を使う場合)
5. 有効期限を決めて **Generate token**。表示された `github_pat_…` をコピー
6. 入力ツールの「GitHub アクセストークン」に貼り付けて **接続**

トークンはブラウザから GitHub(api.github.com)にだけ送られます。既定ではタブを閉じると
消えます。自分専用の端末なら「この端末にトークンを保存する」にチェックしても構いません。
トークンはパスワードと同じ扱いをしてください(メールやチャットに貼らない)。

## 2. 論文を1本登録する

1. **データセット** → 右上の **+ EXP**(実験データの場合)
2. **DOI** を入力して **書誌情報を取得**。著者・誌名・年などが Crossref から自動で入り、
   文献データベース(`data/master/bibliography.json`)に保存されます。
   - DOI のない文献は **DOI なし…** を押し、名前(例 `Suzuki1975thesis`)を付けます
     (`10.1000/mund.Suzuki1975thesis` という仮の DOI になります)。書誌情報は手で入力します。
   - arXiv 版・訂正・データの DOI は「関連 DOI」に入れます。
3. **実験条件**: 施設を選び、手法・ビーム・標的・検出器を書きます(自由記述)。
   施設が一覧にない場合は **マスタデータ** で追加してから選びます。
4. **データ点**: 「+ 行を追加」で1行ずつ入力するか、**貼り付け…** で表計算ソフトから
   まとめて貼り付けます。
   - 列の順番は 元素, 質量数, 値, 不確かさ, [Key], [コメント]
   - 質量数 0 は天然同位体比の標的です
   - 値と不確かさは**論文に書かれた桁のまま**入力します(例 `13.250`)
   - 不確かさが書かれていない場合は空欄にします
   - 論文が統計誤差と系統誤差を分けて書いている場合は、表の上の
     **「統計・系統誤差を分けて入力」** にチェックを入れ、「± 統計」「± 系統」の列に入力します
     (「± 全体」は空欄で構いません。換算値には二乗和が使われます)
   - 実験データには、寿命・捕獲率・捕獲確率のうち**論文に最も近い量を1つだけ**入力します
   - 同じ核種の行が複数あるときは **Key**(例 `plate` / `powder`)で区別します
5. 右側の表示を確認します。
   - **換算値**: 寿命を入れた行には捕獲率が、捕獲率を入れた行には寿命が出ます
   - **確認**: 評価値と大きくずれていると「⚠ 要確認」になります(元素や桁の打ち間違いの発見用。
     本当にずれているデータならそのままで構いません)
   - **DataID**: 自動で計算されます
6. 画面下の **チェック結果** が「問題なし」になっていることを確認します。
   赤い項目を押すと該当の欄に移動します。

キュレーションデータ(**+ CUR**)では、各行の「元データ」に元になった実験データを指定します。
「…」ボタンを押すと、同じ元素の実験データの一覧から選べます。キュレーション・評価データの値は
捕獲率(µs⁻¹)に統一します。

## 3. コミットする

入力した内容はブラウザに自動保存されますが、まだ誰にも見えていません。

1. **未コミットの変更** を開く
2. ファイルごとの差分(赤 = 削除、緑 = 追加)を確認する
3. 「変更内容の説明」を書く(1行目が見出しになります。例: `LT/EXP: add Suzuki1987`)
4. **main にコミット** を押す

数分後に公開サイトの latest に反映されます。誰がいつ何を変えたかは **履歴** で見られます。

- **Pull Request(レビューしてから反映)** を選ぶと、main には入らず、ブランチと Pull Request が
  作られます。他の人に見てもらってからマージしたい場合に使います。
- エラーが残っているとコミットできません(警告だけなら可能です)。
- 「ほかの人がこのファイルを先に更新しました」と出た場合は、**再読み込み** してから
  変更し直してください。相手の変更を上書きすることはありません。

## 4. 修正する

データセットの一覧からファイルを開いて直し、同じようにコミットします。

- **値・不確かさ・コメント・実験条件を直しても ID は変わりません。**
- **元素・質量数・Key・DOI を直すと ID が変わります。** 以前の ID は「旧 ID」として自動的に
  記録され、その ID を参照していたキュレーションデータも自動で書き換えられます。
- 「変更を破棄」で、そのファイルの未コミットの変更を取り消せます。
- コミット済みの内容を戻したい場合は、GitHub の履歴から該当コミットを Revert するか、
  値を直してもう一度コミットします。過去の状態はすべて残っています。

## 5. JSON を直接編集する

エディタの **JSON** タブで、ファイルの中身をそのまま編集できます(Monaco Editor)。
スキーマに基づく入力チェックと補完(Ctrl+Space)が効きます。**反映** を押すと、ID の再計算と
書式の正規化が行われてフォームに取り込まれます。**差分** タブでリポジトリとの違いを確認できます。

## 6. リリース(版番号を付ける)

**リリース** ページで、パッチ / マイナー / メジャーを選び、変更点を書いて実行します。
`VERSION` と `CHANGELOG.md` が更新され、タグ `vX.Y.Z` が作られます。

- **メジャー版(v1.0.0, v2.0.0 …)だけが、公開サイトで固定バージョンとして選べるようになります。**
  外部の利用者に引用してもらうのはこの版です。
- パッチ・マイナーは Git の履歴として残ります。
- タグは後から変更できません。

詳しくは `docs/versioning.md`。

## 困ったとき

| 症状 | 対処 |
|---|---|
| 接続できない(401) | トークンが間違っているか期限切れ。作り直す |
| 接続できない(404) | リポジトリ名・ブランチ名、トークンの Repository access を確認 |
| コミットできない(403) | トークンの Contents 権限が Read and write になっているか、リポジトリの書き込み権限があるか |
| JSON エディタが簡易表示になる | Monaco Editor を CDN から読み込めなかった場合の代替表示。機能は同じです |
| 入力途中でブラウザを閉じた | 下書きは同じブラウザに残っています。もう一度開けば続きから |
